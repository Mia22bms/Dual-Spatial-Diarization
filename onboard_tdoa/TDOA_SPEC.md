## 0. 范围

**做**：对每一帧估计一个**主导方向**，输出 τ、θ、confidence、voiced。

**不做**：分离重叠说话人、数人数、算位置 (x, y)、两板时间对齐。

## 1. 硬件与输入

- 板子：ESP32-S3-AUDIO-Board，两麦间距 `d = 0.036 m`
- WAV 的**采样率、位深、声道数一律从文件头读取**，不得写死；必须支持 16-bit 和 24-bit

### 1.1 轨号与数组下标（Python 从 0 开始数）

| Audacity 轨号 | 数组列下标 | 含义 |
|---|---|---|
| 1 | 0 | 不用 |
| **2** | **1** | **MIC1** |
| 3 | 2 | 不用 |
| **4** | **3** | **MIC2** |

## 2. 几何与符号约定

### 2.1 角度定义

- `0°`：垂直于两麦连线，朝麦所在板边往外（板子前方）
- `+90°`：沿两麦连线指向 **MIC1**
- `−90°`：沿两麦连线指向 **MIC2**
- 有效范围 `[−90°, +90°]`。板子后方的声源与前方镜像，无法区分，不在测量范围内

### 2.2 τ 的定义

```
τ = TOA(MIC2) − TOA(MIC1)
  = 声音到达 MIC2 的时刻 − 声音到达 MIC1 的时刻
```

声源在 MIC1 一侧时，声音先到 MIC1、后到 MIC2，所以 τ > 0；再经过 §2.3 的公式得到 θ > 0，正好对应「MIC1 一侧为正」。全流程不需要任何手动翻转正负号。

数字例子：声源在 +30° → τ = 0.036 × sin30° ÷ 343 ≈ **+52.5 µs** → θ = **+30°**。

### 2.3 几何公式

平面波近似：

```
τ = d·sinθ / c   ⇒   θ = arcsin( c·τ / d )
```

- `c = 343 m/s`（约 20 ℃）。温度每差约 17 ℃，c 约差 1%，会按比例影响角度
- `d = 0.036 m`

### 2.4 物理上限与出界处理

```
τ_max = d / c = 0.036 / 343 ≈ 104.9 µs
```

令 `x = c·τ / d`：

1. `|x| ≤ 1`：正常换算
2. `1 < |x| ≤ 1 + m`（`m = 0.1`）：把 x 夹到 ±1，角度记为 ±90°，confidence × 0.5
3. 因为峰的搜索范围限制在 `±(1+m)·τ_max`（见 §3 第 7 步），`|x| > 1 + m` 不会出现
4. `tau_us` 列**照实记录原始 τ**（含轻微越界值），方便诊断。出界的 τ 本身就是信号：说明噪音或反射在干扰

## 3. 处理流程

1. **读 WAV**，取 `[--start, --end]` 时间段（默认整个文件）
2. **分帧**：帧长 N、帧移 H（按毫秒定义，再按实际 fs 换算成采样点数）；两路都乘同一个 Hann 窗
3. **energy VAD**（见 §4）：非 voiced 帧直接写 `voiced = 0`，`tau_us`、`angle_deg` 记 NaN，`confidence = 0`，跳过后续步骤
4. **FFT**：长度 L = 不小于 2N 的 2 的幂（避免循环互相关的回绕）
5. **互谱**：
   ```
   G(f) = X2(f) · conj(X1(f))
   ```
   **顺序不能反**：用 X2·conj(X1)，峰才会出现在 +τ；如果写成 X1·conj(X2)，峰会出现在 −τ，整张图左右镜像
6. **PhaT 加权与频带**：
   ```
   R(f) = G(f) / (|G(f)| + ε)
   ```
   只保留 125–3500 Hz 的频点，其余置 0
7. **逆变换 + 插值 + 找峰**：频域补零到 L × interp 后做逆 FFT，得到 GCC 曲线 r(lag)；只在 `lag ∈ [−(1+m)·τ_max, +(1+m)·τ_max]` 内找最大值，其位置即 τ
   - **不使用抛物线拟合或任何其他亚采样点细化方法**
   - `--interp 1` 时必须严格只取整数个采样点的峰。否则「插值 vs 不插值」的对照会失效
   - 逆变换用实数逆 FFT（如 `irfft(R, n = L × interp)`），保证 GCC 曲线是实数
8. **换算角度**：θ = arcsin(c·τ/d)，按 §2.4 处理出界
9. **算 confidence**（见 §5）
10. **写出一行 CSV**

---

## 4. energy VAD

- **帧能量** E = 该帧 MIC1、MIC2 两路的平均功率（加窗前、每个采样点平方后取平均）
- **噪声底**：
  - 默认 = **整个文件**所有帧能量的第 10 百分位
  - 理由：不依赖专门的安静段（REC_006 开头不一定安静）；而受控测试的文件里有开头 5 s 和每个角度之间 2 s 的安静，第 10 百分位会落在这些安静帧上。用整个文件而不是分析时间段，是因为分析的时间段可能全程都有声音（比如只分析手机播放的 15 秒），那样估出来的"噪声底"其实是声音本身
  - 全文件分帧时，帧长、帧移与分析用的完全相同
  - 可选：`--noise-start`、`--noise-end` 手动指定一段安静时间，优先于默认方法
- **门槛**：`E > 噪声底 × 10^(vad_db / 10)`，默认 `vad_db = 6 dB`
  - 这是**能量**的 dB：+6 dB = 能量 ×4 = 幅度 ×2
  - 起点值，可按实测调
- 运行时打印：噪声底数值、voiced 帧占比

## 5. confidence

直觉：每个频点都按自己的相位「投票」说时间差是多少。confidence = 选定的 τ̂ 得到的**平均同意程度**。

```
confidence = (1/K) · Σ_{频带内的频点 f}  Re{ R(f) · e^{+j·2π·f·τ̂} }
```

- **只在单边正频率上求和**：Σ 只包括 125–3500 Hz 范围内的正频点；K = 这些正频点的个数
- 完美对齐（单一声源、无噪音、无反射）时，每个频点都完全同意 → confidence = **1**
- 纯噪音时，各频点方向随机、互相抵消 → confidence ≈ 0
- 结果夹到 [0, 1]，再乘 §2.4 的出界惩罚
- **实现时直接按上面的定义求和，不要从逆 FFT 的峰值反推**：逆 FFT 的 1/N 归一化加上单边/双边频谱混用，很容易把系数弄错（例如干净信号得到 0.5 而不是 1）
- 合成测试中，干净信号的 confidence 应该接近 1（加窗和小数延迟会让它略低于 1）

## 6. 参数表

| 参数 | 命令行 | 默认值 | 理由 |
|---|---|---|---|
| 帧长 | `--frame-ms` | 64 ms | 静止单一声源（合成测试、受控测试）下，帧越长，互谱估计越稳，峰越稳。注意：语音本身只在 20–30 ms 内近似平稳；真实对话中，长帧会让跨换人时刻的帧变多，产生「两人之间的假方向」，以后跑真实对话时应调短 |

## 7. 插值：分辨率 vs 准确度

| fs | 1 个采样点 | τ_max 合几个采样点 | 不插值时的角度档位 |
|---|---|---|---|
| 16 kHz | 62.5 µs | ±1.68 | 0°、±36.6°（只有 3 个） |
| 48 kHz | 20.8 µs | ±5.0 | 0°、±11.5°、±23.4°、±36.7°、±52.6°、±83° |

- `--interp 8` 在 16 kHz 下：每档 62.5 ÷ 8 ≈ 7.8 µs，±τ_max 内单侧约 13 档
- 插值方法：频域补零，等价于时域 sinc 上采样
- **插值提高的是读数分辨率，不是准确度。** 噪音、反射、混叠会让 GCC 的峰本身偏离真实位置，插值只会把偏掉的峰读得更精细。准不准只能由真值测试（合成信号、受控角度测试）判断
- 解释结果时必须注明 fs 和 interp

## 8. 频带上限与空间混叠

GCC-PhaT 依靠每个频点的相位差 `Δφ = 2π·f·τ`。要让相位差和 τ 一一对应，最大延迟下的相位差不能超过 π：

```
2π·f·(d/c) ≤ π   ⇒   f ≤ c / (2d) = 343 / 0.072 ≈ 4764 Hz
```

- 高于约 4.76 kHz 的频点，相位会绕过一圈，同一个相位差对应多个 τ，产生假峰
- 上限取 3500 Hz（约为混叠频率的 0.73），留出余量；语音中对定位有用的能量大多也在 3.5 kHz 以下
- 推论：16 kHz 采样（可录到 8 kHz）已经包含了这对麦能用于定位的全部频率；提高采样率不会增加可用频带

## 10. CSV 规范

每帧一行，列顺序固定（以后的 C 版本输出完全相同的格式）：

| 列名 | 类型 | 说明 |
|---|---|---|
| `time_s` | float | 该帧中心在**整个文件中**的时间（秒），不是从 `--start` 重新算，方便与 Audacity 和录音记录对照 |
| `tau_us` | float | τ = TOA(MIC2) − TOA(MIC1)，微秒，照实记录；非 voiced 帧为 NaN |
| `angle_deg` | float | [−90, +90]；非 voiced 帧为 NaN |
| `confidence` | float | [0, 1]，见 §5；非 voiced 帧为 0 |
| `voiced` | int | 1 = 有声，0 = 安静 |

## 12. 验证计划

### A. 合成信号测试（`test_synthetic.py`）

用代码自己生成已知延迟的两路信号，检验算法本身：

- 源信号：白噪音，以及一段语音
- MIC2 相对 MIC1 延迟 τ = d·sinθ / c，用**频域相移**实现小数个采样点的延迟（不能用整数平移）
- 角度：0°、+30°、−30°、+60°、+90°
- 条件：fs = 16 kHz 和 48 kHz；无噪音和 SNR ≈ 10 dB；`--interp 1` 和 `--interp 8`
- 输出表格：真实角度、真实 τ、算出的 τ、算出的角度、误差、confidence

通过标准：
- **正负号全部正确**：+30° 必须输出正角度
- 抽查：16 kHz、+30° → τ ≈ +52.5 µs
- 无噪音、`--interp 8` 时误差应远小于一档（37°），记录实际误差
- 无噪音时 confidence 接近 1
- `--interp 1` 时角度只落在 §7 表中的档位上

这一步**测不出**轨号接错（因为信号是代码自己造的），见 §1.1。

### B. 真实录音跑通（`Board2_REC_006.wav`）

- 挑一段只有一个人说话的片段（避开厨房里的未标注人声）
- 只用于调通流程、找 bug，**不判断准不准**（没有真值）
- 检查：没人说话时 voiced = 0；有人说话时角度大致成一条线

### C. 受控角度测试

手机在已知角度播放，是唯一能判断准确度的测试。流程见 handoff §4。
